# 3D rendering — Cornell Box

The standalone `tests/Radiant.3D` project uses Radiant's ECS, desktop props, renderer API, shader registry and F1 framework inspector. Its scene contains five room surfaces, two rotated blocks and a ceiling emitter.

`Transform3D` stores world position, Euler rotation in radians and scale. `Mesh3D` references immutable triangle geometry and an opaque base color; `Camera3D` defines a right-handed perspective camera with Y up. `SurfaceEmission` is optional HDR radiance. A game may use compact `Transform2D` components on other entities, or both representations on one entity.

Camera entities can optionally have a `Transform3D`: its position and Euler rotation then define camera pose, while `Camera3D` retains lens settings. Camera scale is ignored. Without a transform, Position / Target / Up continue to define pose. The same rule applies to `Camera2D` with `Transform2D`, keeping Zoom in the camera component.

Open F1 → ECS → Open Entity Inspector, search `Camera3D`, and select a row. Entity Properties edits public component fields live, including vector axes, transforms and lens settings. Camera controls assigns the selected camera to a specific view and enables navigation: hold RMB over the scene, use WASD / Q E, and hold Shift for faster movement. Choose the view explicitly when an entity has both camera dimensions. Changes propagate to flat, raster, path tracing and radiance cascades; camera motion resets progressive tracing but reuses the cascade field. The Cornell demo updates its orbit camera only on arrow-key input, preserving editor changes between inputs.

The pipeline uses CPU mesh extraction (`MeshGeometry3D`), optional raster geometry buffers (`Geometry3D`), selectable flat/raster/path tracing/radiance cascade image producers, optional tone mapping and post AA, UDR reconstruction, and explicit presentation. Raster producers also support geometry MSAA/SSAA. The standalone demo starts maximized with path tracing selected; regression scenes retain their explicit settings. R cycles all four rendering modes; F1 opens settings; Tab cycles available buffers from the active pipeline without changing producer output contracts. Path tracing exposes optional ray-derived albedo, normals, linear depth and HDR emission. Radiance cascades expose cascade atlases, irradiance and linear depth; both tracing modes release raster targets.

Start directly with the optimized cascade configuration:

```sh
dotnet run --project tests/Radiant.3D -c Release -- --radiance-cascades
```

First activation selects a 16³ probe grid and UDR4 Balanced. Subsequent renderer
switches retain reconstruction choices. The lighting stage performs at most 32
bounce updates before reusing an unchanged field; its limit is adjustable, with
zero meaning continuous updates. See [3D radiance cascades](RadianceCascades3D.md)
for the research, measured costs, limitations and regression commands.

| Geometry output | Format | Meaning |
| --- | --- | --- |
| Color | Color | Unlit opaque RGB; background alpha zero |
| Normals, optional | Color | World normal encoded as `normal * 0.5 + 0.5`; background alpha zero |
| Depth, optional | Single | Positive linear view depth divided by FarPlane; background zero |

Color-only is the geometry system's default. The sample requests all three outputs for inspection. Hardware depth resolves raster visibility (configurable `VisibilityFormat`, tested stable default Depth16); normals use the inverse transpose, including nonuniform scale. Opaque meshes cull back faces by default, with winding corrected for mirrored transforms. Set `Mesh3D.DoubleSided = true` for thin/open surfaces that need both sides rasterized. Buffers are recreated on resize and released when switching to path tracing or radiance cascades. Mesh vertex/index buffers are cached by Renderer and released with it.

See [modular rendering](Rendering.md) for composition examples, independent views, 2D support, path tracing limitations, memory/lifetime behavior, source migration and validation commands.

Color and AA controls live in the shared **Color Management** and **Antialiasing** windows under F1 → View. `ColorSettings` and `AntiAliasingSettings` bind individual processor instances and work with either dimension; see [shared rendering settings](Rendering.md#shared-color-and-settings-windows).

F1 → View → **Path tracing** includes an optional denoiser selector: None, Joint bilateral, or À-trous (enabled on normal demo startup), with strength and wavelet iterations. The same `Denoising` system and `PathTracingSettings` window work in the compact 2D demo. Raw path buffers remain available separately; see [denoising composition and references](Rendering.md#optional-path-denoising).
